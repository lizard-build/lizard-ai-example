Один личный sandbox обслуживает все темы. В нём один вход в ChatGPT, а каждой теме соответствует отдельная сессия и папка /workspace/sessions/<topic_id>.

Темы разделяют историю и рабочие папки, но используют одну машину. Это не изоляция между разными пользователями. Бот рассчитан на одного владельца.

Проверки

  • Проверка Telegram ID владельца и чата, включая кнопки подтверждений.
  • Длинные ответы, Unicode и отправка в нужную тему.
  • Защита соединения с Codex, журнал событий, защита от повторного запуска запроса.
  • Отказ для просроченных подтверждений и подтверждений из другой темы.
  • Настоящий локальный PostgreSQL: блокировка второго экземпляра, сохранение очереди и восстановление контроллера.
  • Настоящий Codex CLI 0.153.4: инициализация app-server и чтение состояния чистого аккаунта, без обращения к модели.

Тесты Telegram и задач Codex используют подставные ответы. На Lizard проверены соединение с Managed Postgres, подключение диска, запуск Codex и готовность сервиса. Полный путь «сообщение Telegram → модель → ответ» ждёт включения тем, Start и входа в ChatGPT. Восстановление диска после пересоздания sandbox ещё не проверено.

Команды развёртывания для справки

Эти ресурсы уже созданы, секреты заданы на уровне сервиса, код загружен. Повторно создавать ресурсы не нужно. Для следующей версии достаточно обновить код и вызвать up.

cd /path/to/codex-telegram
lizard init --name codex-telegram --workspace WORKSPACE_SLUG --json
lizard add postgres --json
lizard add --service bot --json
# Задать секреты через lizard secrets import --service bot --json.
# DATABASE_URL: ${{postgres.DATABASE_URL}}
# LIZARD_PROJECT_ID: ID созданного проекта.
# LIZARD_API_KEY: ключ только для этого проекта.
# TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_ID, при необходимости OPENAI_API_KEY.
# Проверить наличие GitHub remote перед выбором способа развёртывания.
lizard up --service bot --port 3000 --json
lizard logs --service bot --json

Команда up подходит текущему локальному проекту без remote. Если появится GitHub remote, сервис нужно подключить к репозиторию и использовать git push to deploy.

Проверка после запуска
  1. Убедиться, что Managed Postgres доступен, а /healthz возвращает 200.
  2. Выполнить /login, пройти вход в ChatGPT.
  3. Создать две темы через /new и проверить раздельную историю.
  4. Создать файл в рабочей папке первой темы, продолжить ту же сессию.
  5. Проверить кнопки подтверждения и /stop.
  6. С согласия владельца перезапустить сервис и затем проверить сохранение данных при пересоздании sandbox.

Текущие ограничения

  • Принимает текст. Вложения, голос и потоковая выдача по токенам пока не добавлены.
  • Отправка ответов в Telegram допускает редкий дубль: если Telegram принял сообщение, а бот не успел записать подтверждение в базу.
  • Прерванные действия с неизвестным исходом требуют проверки перед повтором. Это касается и создания тем.
  • Неподдерживаемые запросы Codex, включая произвольные формы MCP, бот отклоняет.
  • Журналы и сообщения сохраняются без срока удаления. Нужны отдельные правила хранения и резервные копии.
  • GitHub remote не задан. Код можно хранить в личном приватном репозитории после его выбора.
